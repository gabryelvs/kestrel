# Kestrel stage 5: what the build decided and left

Written when stage 5 finished (2026-11-03), from the build's ledger, which is scratch and gets deleted. Each ruling reads:
what was decided, why, and what it costs if wrong. The spec is the authority; where a ruling changed it, the spec says so too.

## Rulings made during the build

- power::create_and_activate no longer reads the prior; a new power::prior gives it, and the engine journals the intent before creating anything — the spec requires the old value on disk before each change — cost if wrong: none, this only reorders two calls.
- an unsettled plan record with Kestrel's plan on disk becomes Outcome{interrupted}, showing Kestrel's plan isn't active; with no plan on disk it closes NotApplied — the spec says a crash before activation needs no special handling and lands in that state — cost if wrong: an interrupted apply shows a row asking to remove a plan, one extra click.
- Engine::report belongs to Task 8; Engine::turn_protection_on and record_restore belong to Task 10; Task 7 handles SystemProtection records with hand-written journals in its tests — keeps each task's deliverable testable alone — cost if wrong: none.
- targets::describe covers every Saved variant, because the report needs plan names and protection states — cost if wrong: none.
- WinSystem::with_signed_in(sid), used only by the round-trip binary, handles a runner with no shell — the engine must not grow a fallback that could write to the elevating account's hive on real PCs — cost if wrong: the round trip tests the elevating account instead, which on a runner is the same account.
- run_helper off Windows returns Skipped without spawning — the Mac has no restore points — cost if wrong: none, dev only.
- kestrel-tweaks depends on kestrel-core and kestrel-probe by path only, as the app does — avoids a version line to bump — cost if wrong: none.
- no separate System Protection stage-5 test on CI — windows-latest may have no System Restore (unverified) and the spec already sends it to the owner's PC — cost if wrong: the restore point's first real run is on the owner's PC.
- FakeSystem's set_mouse_live(persist) writes the caller's profile (this_process), not signed_in — that is what SPIF_UPDATEINIFILE does, and the over-the-shoulder path depends on the difference — cost if wrong: one token in the fake.
- a value_name matches ignoring case with either slash before VALORANT-Win64-Shipping.exe, and a failed Outcome of a later intent leaves an already-open record standing — Task 5 can return an existing lower-case spelling, and a failed re-apply must not orphan the first change — cost if wrong: a looser filter on a value name that is only ever used in one registry key.
- an open record keeps a windowed row visible even below build 22621, and a GPU token other than absent, 0, 1 or 2 is Couldn't read — an applied tweak must never vanish from the list, and an unknown value must not be overwritten — cost if wrong: a row shown on a PC that can't use it, with Undo working.
- an open record decides the plan row before NotOffered and policy, as Task 5 ruled for the settings, and create_and_activate reads each value back — Undo must survive a later policy, and the spec says write then read back — cost if wrong: an Apply rolled back on a machine that rewrites a plan value, visible in the round trip.
- "with the clamp recorded" in the spec becomes "the Preview shows the clamped value" — the Preview already shows what will be written, nothing downstream reads a recorded clamp, and it's rare — cost if wrong: the report doesn't say a value was clamped, though the plan's value is readable in Windows.
- on Task 7's readings: "Already set." only for AlreadySet and Applied, other rows give their own why; Apply again and Use it again write a later intent first; Apply settles the journal first under its lock; Restore anyway closes a value already at the prior as WentBack with no write and refuses an unreadable value, the plan and System Protection; System Protection's undo is refused unless protection() says on and the prior is off; the plan is read back after create_and_activate — each one is the safer reading of the spec, the journal's documented shape or an honest message — cost if wrong: one line each in engine.rs.
- Apply leaves a flagged row alone and answers with the row's reason, against the brief's "Available or ChangedElsewhere" — the spec's anti-goal says a value Kestrel didn't write is never overwritten without asking, the Preview doesn't list that row, and Apply again is the asking — cost if wrong: none for a person, since the page gives a flagged row only Apply again and Restore anyway.
- a report's Active list is judged by standing == Holds for the signed-in account and machine-wide, read-only, and replaces the settled filter — the spec binds "Applied rows only" and report() must never write — cost if wrong: an Active line missing for a change cut off by a crash until the next look, which the journal's History still shows.
- Undone with no detail on a plan record prints "Undid Kestrel power plan: removed Kestrel's plan and left the plan in use alone", and an interrupted outcome prints "Kestrel was interrupted while applying X: a → b" — remove_recorded_plan writes None and the plan in use stays, and an interrupted change must not read as a plain success — cost if wrong: one wording in report.rs.
- System Protection counts under the report's Active only if it holds, while applied_ids lists it while its record is open — the report doesn't reconcile, and the stricter side never claims what protection() couldn't confirm — cost if wrong: System Protection missing from Active while protection() can't be read, with its History line still there.
- SPIF_SENDCHANGE goes, replaced by SendNotifyMessageW(HWND_BROADCAST, WM_SETTINGCHANGE, SPI_SETMOUSE, 0) — the broadcast can block on one hung top-level window while the journal lock is held, SPI_SETMOUSE takes effect without it, and a notification that returns at once does the same job — cost if wrong: Mouse Properties left open shows the old state until reopened.
- an absent value under a readable SPP\Clients key is ProtectionOff, a missing key is Unknown — Sophia and a published turn-off REG read it that way, and otherwise decision 89's dialog never shows or Undo can't close — cost if wrong: the dialog offers to turn on what's on, and Enable on an enabled drive is harmless.
- ReturnValue 1717 goes on to polling, and a turn-on that errors while protection now reads Ready counts as applied — the poll of protection() is the truth, PowerShell's source allows 1717, and a change Kestrel made must keep its undo — cost if wrong: a 30-second wait before the same failure.
- turn_protection_on reads protection() first and writes a record only if it reads off — a record saying off, whose undo deletes the drive's restore points, must never be written without looking — cost if wrong: none in the dialog's flow.
- a missing SPP\Clients key also counts as off, replacing "missing key is Unknown" — a never-enabled client gets the offer, and an Undo that removes the key can close — cost if wrong: a Server with no System Restore gets an offer that fails with a sentence.
- ERROR_SERVICE_DISABLED stays a Failed with Continue and Cancel, and the spec is amended — RestoreOutcome can't carry the signal, and after the ruling above it only arises where the registry says on and Windows says disabled — cost if wrong: that rare PC isn't offered Turn on and create, and Kestrel's undo is unaffected.
- --tweaks-revert-all exits 3 when the journal still holds any open record afterwards, rather than when an item has ok:false — it also catches another account's records, which revert_all skips — cost if wrong: the uninstaller says something was left when an item's failure already closed, which can't happen by the record rule.
- an unreadable process list closes the gate with a new Gate::CantTell, "Kestrel couldn't check whether VALORANT is open. Try again." — the gate is what keeps a change away from a running game, so "can't tell" must not read as "not running", while the benchmark's shared function keeps its own safe default — cost if wrong: a person retries once on a machine whose list briefly fails.
- "Expect a small gain at most" becomes "The difference may be small or none: measure it on your PC", and "the faster way" goes from the windowed row — the owner's rule is that the copy never promises a gain, and a hedge still tells the person to expect one — cost if wrong: one sentence.
- the page waits at most 20 seconds for the rescan before showing a result, and a coalesced scan frees its slot after 60 — the change is already made, and a stuck WMI or NVML query must not hide it or block later ones — cost if wrong: a benchmark started right after Apply on a very slow machine records the old plan name.
- Health's "hurts 1% lows" becomes "can hurt 1% lows" — it sat as a stated fact next to the hedged Tweaks row, and research puts the plan's effect at 0-3% — cost if wrong: one sentence.
- the first-run button keeps its stage-2 label "Later" though the spec says Not now — decision 42 named it and it's the same control — cost if wrong: one string.
- hooks.nsh uses ClearErrors and treats a program that couldn't start as no answer — ExecWait leaves its variable undefined then, and NSIS compares an empty variable as 0 — cost if wrong: none.
- the uninstaller deletes the journal's two files and removes the folder only if empty, with the path from the shell API, instead of RMDir /r on an environment variable — NSIS's recursion follows reparse points, and the project treats that folder as pre-creatable by a standard user — cost if wrong: a stray file leaves an empty-looking folder behind.
- the README's older stage paragraphs go to past tense, against "keep the older paragraphs" — a present "changes nothing" would be a false safety statement now — cost if wrong: two words.
- the final fix dispatch takes Issues 1-6, Minors 1-6, 8, the "Restart VALORANT" and "in another window" sentences of 10, and the Lock In "boosts" line — what a person sees on the first real run, and what they'd need to report a failure — cost if wrong: a few small changes to re-check.
- the uninstaller gets an exit 4 and its own message when only System Protection is left, against the plan's single message — spec line 307 says the uninstaller says what's left, and the plan's wording would fire on every uninstall after Turn on and create — cost if wrong: one more exit code.
- tabs lock while a Tweaks step is busy, as every busy step is bounded (helper 180 s, turn-on about 210 s, scan wait 20 s) — the page remounts on a tab change, which loses the result, the question, or a refusal's reason — cost if wrong: up to 3 minutes where the person can't change tab during a restore point.
